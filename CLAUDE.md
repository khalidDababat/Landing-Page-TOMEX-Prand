# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev:all      # Start json-server (port 3001) + Next.js dev server (port 3000) together — required: Home (Services, Team), Portfolio and Careers all fetch from it
npm run dev          # Next.js dev server only
npm run server       # json-server only (data/db.json), port 3001
npm run build        # Production build
npm run start        # Start production server
npm run lint         # ESLint
npm run format       # Prettier --write src/**/*.{ts,tsx,scss,json}
npm run typecheck    # tsc --noEmit
```

There is no test suite configured in this repository.

Env vars (no `.env.example` is checked in; set these in `.env.local`):
- `API_URL` — json-server base URL for **server-side** fetches. Server-only (no `NEXT_PUBLIC_` prefix), read at runtime, never reaches the browser.
- `NEXT_PUBLIC_API_URL` — same API, for **client-side** fetches (Careers and Services still fetch in the browser). Inlined at build time.
- Resolution in `services/apiClient.ts`: `API_URL` → `NEXT_PUBLIC_API_URL` → `http://127.0.0.1:3001`. In the browser `API_URL` is `undefined`, so the same module works on both sides.
- `RESEND_API_KEY`, `CONTACT_EMAIL`, `EMAIL_FROM` — required by the `/api/contact` route handler (see Contact form below); missing `CONTACT_EMAIL`/`EMAIL_FROM` makes the route return a 500 without calling Resend.

Don't run `npm run build` while `npm run dev:all` is running — it overwrites the `.next` folder the dev server uses.

## Architecture

Next.js 16 (App Router) + React 19 + TypeScript + SCSS Modules. Material UI is used for icons only (`@mui/icons-material`) — no CSS-in-JS/MUI components for layout or styling.

**Routing & pages** (`src/app`): `/` (Home), `/careers`, `/careers/[id]` (opportunity detail), `/api/contact` (route handler, not a page). The Portfolio route currently lives in `src/app/_portfolio/` — the `_` prefix makes it a Next.js private folder, so `/portfolio` is **not routed** (it 404s) while the portfolio isn't public; the header's Portfolio link shows a "coming soon" toast instead (`comingSoon: true` in `utils/navigation.ts`). Rename the folder back to `portfolio` to re-enable it; references to `/portfolio` / `app/portfolio/*` below describe it as it works when enabled. Unknown routes render `not-found.tsx`, a standalone 404 page (own markup — "404" heading, message, "Go Back Home" link — imports `globals.scss` directly). Home is composed directly in `src/app/page.tsx` (Hero, About, Services, Team, Contact from `src/sections`, in that order; there is no `views/Home`). Portfolio, Careers and the careers detail page compose in `src/views/{Portfolio,Careers,CareerDetails}`, with `app/portfolio/page.tsx`, `app/careers/page.tsx` and `app/careers/[id]/page.tsx` as thin route entries that await `params` and export page `metadata`. `app/portfolio/loading.tsx` and `app/careers/[id]/loading.tsx` are the two routes' loading UI; `app/error.tsx` is a root-level client error boundary for unexpected render errors.

**Data flow** — two different content sources feed the same pipeline shape:
- Hero, About, Contact and the footer are static, hardcoded in their own components.
- The Home `Services`/`Team` sections, Portfolio and Careers content come from `json-server` over `data/db.json`. Each top-level key in `db.json` (`services`, `projects`, `jobs`, `team`) is its own REST endpoint; page headings for Portfolio/Careers are hardcoded in the views.
- Shared base of the pipeline: `services/apiClient.ts` (`getResource`; the only module that fetches the content API — owns base URL, headers, `cache: 'no-store'`, `ApiError` shape; used from both server and client code) → `services/contentService.ts` (typed per-page fetchers: `fetchServices`, `fetchPortfolio`, `fetchCareers`, `fetchJob(id)`, `fetchTeam`). The contact form does not use this pipeline — see Contact form below.
- The pipeline then **differs per page**, because the migration to server-side fetching is in progress:
  - **Portfolio, careers detail (`/careers/[id]`) and the Home `Team` section — server-fetched.** `views/Portfolio` and `views/CareerDetails` are async Server Components that await `fetchPortfolio()` / `fetchJob(id)`; `sections/Team` is an async Server Component awaiting `fetchTeam()` directly in the Home tree (not behind its own route). All three catch fetch errors themselves and render the shared states from `components/common/AsyncContent/` (`ErrorState`, `EmptyState`) in place, so a failure never throws to an error boundary — `CareerDetails` additionally calls `notFound()` for a non-numeric `id` or a 404 from the API. While `/portfolio` or `/careers/[id]` is pending, their `loading.tsx` renders `LoadingState`; `Team` has no route-level loading UI since it's embedded in the Home page. Because of the `no-store` fetch, `/`, `/portfolio` and `/careers/[id]` are all dynamic (`ƒ`) — no `force-dynamic` export is used anywhere.
  - **Careers list and Home `Services` — still client-fetched.** They are Client Components using `hooks/useFetch.ts` (generic `{ data, status, error, retry }` hook, aborts in-flight requests on unmount) → `AsyncContent/AsyncContent.tsx` (renders loading / error+retry / empty from a `status` value so the page only writes its success case). They fetch in the browser via `NEXT_PUBLIC_API_URL`.
- **Retry on server-fetched pages** is `AsyncContent/RetryButton.tsx` (client): `router.refresh()` inside `startTransition`, which re-runs the server fetch (a real new request). `error.tsx`'s `reset()` alone would not refetch, so `app/error.tsx` also calls `router.refresh()`. The `Team` section has no retry button (no route to refresh independently) — a refresh of `/` re-fetches it.

**Server vs Client components**: Server Components are the default. `'use client'` is deliberately scoped to components that need interactivity/state: `Header` (menu state & scroll lock), `Toast` (the `ToastContainer`), `ScrollManager` (hash-scroll), the `Contact` section and `ApplicationForm` (form state), `ComingSoonButton` and `RetryButton` (click handlers), `app/error.tsx` (error boundaries must be client components), and — until they are migrated — the `Services` section and `Careers` list view (client-side `useFetch`).

Server Components: `views/Portfolio` and `views/CareerDetails` (async, fetch data), `sections/Team` (async, fetches data), the Home page (`app/page.tsx`), `Hero`, `About`, `Footer`, `WhatsAppButton`, `SocialLinks`, `ProjectCard`, `JobCard`, `TeamMemberCard`, `Badge`, `Button`, `ButtonLink`, `SectionTitle`, and the `AsyncContent` `LoadingState`/`ErrorState`/`EmptyState`. A Server Component cannot pass function props to a Client Component, so click handlers live inside small client leaves (`ComingSoonButton`) instead of being passed down as callbacks. `JobCard` no longer takes an `onApply` prop or shows a toast — it resolves its apply action via `utils/careers.ts`'s `getApplyTarget` and renders a plain `ButtonLink` to either `/careers/[id]` or an external URL. When adding new UI, keep it a Server Component unless it genuinely needs state, effects, or browser APIs.

**Known streaming caveat**: MUI icons render through Emotion. Inside a streamed region (a `loading.tsx` fallback resolving, or a `Suspense` boundary) Emotion's inline `<style>` tag causes a React hydration mismatch (error #418) unless `@mui/material-nextjs`'s `AppRouterCacheProvider` wraps the app, which this repo does not yet include. It reproduces on `/portfolio` when the API is slow enough for the loading state to show.

**Navigation vs content**: header/footer links are not part of the content data layer — they're typed constants in `src/utils/navigation.ts` (`HEADER_NAV_LINKS`, `FOOTER_NAV_LINKS`) alongside a `ROUTES` map; Footer renders them via `SmartLink`, Header uses `next/link` directly. On `/`, Header hash links intercept the click and call `useHashScroll`'s exported `scrollToHash` themselves (Next's router ignores a click on the URL you're already at and its `pushState` fires no `hashchange`), so they scroll on every click; the mobile menu closes on link click. In-page links use absolute hashes (`/#about`); `useHashScroll` handles scrolling to the anchored section after navigation, which is what makes anchors work correctly from any page (not just `/`).

**Key reusable components** (`src/components/common`): `Badge` (one component for both job-type and project-technology tags via `size` prop), `ProjectCard` (single component covering all three portfolio bento layouts, selected by a `variant` field — `overlay`/`stacked`/`split` — in the data itself), `SmartLink` (renders a nav entry from `utils/navigation.ts` as a Next.js link; used by Header and Footer), `Button` (a standard `<button>` accepting native button props, with `primary`/`accent` variants — `accent` being the mint outline used for "Apply Now"; it never renders a link), `ButtonLink` (the link counterpart sharing `Button`'s classes: site-absolute `href`s (`/...`) use `next/link`, anything else opens in a new tab via a plain `<a>` — used for "Apply Now" and the careers-detail "Back"/external-apply actions), `ComingSoonButton` (client wrapper rendering a plain `<button>` that fires `showComingSoonToast`, so `ProjectCard` keeps its custom link styling), `WhatsAppButton` (static floating `wa.me` link, rendered once from the root layout), `SocialLinks` (renders a row of brand-colored social links from data, via `utils/iconRegistry.ts`'s `socialIconRegistry`), `TeamMemberCard` (Team section member card), `ApplicationForm` (client; per-job-type fields for the careers detail page — see below).

**Internationalization (EN / AR)**: no i18n library; the language lives in the `tomex-locale` cookie (default `en`, no URL prefix). `src/i18n/`: `config.ts` (locales, `DIRECTIONS`, cookie name), `en.ts` (typed dictionary, source of truth) / `ar.ts` (`Dictionary`-typed, so a missing key fails `typecheck`), `server.ts` (`getLocale()`, `getTranslations()` — read the cookie via `cookies()`), `I18nProvider.tsx` (`useTranslations()`/`useLocale()` for Client Components, mounted once in the root layout with the active dictionary only), `actions.ts` (`setLocale` server action), `format.ts` (`{placeholder}` interpolation). Server Components call `const t = await getTranslations()`; Client Components call `useTranslations()`; shared presentational components that must work from both (e.g. `JobCard`) take translated labels as props. `LanguageSwitcher` (client) calls `setLocale` then `router.refresh()`. The root layout sets `<html lang dir>` and `generateMetadata` is per-locale, so every route is dynamic. `utils/validation.ts` and `services/contactService.ts` receive the relevant `t.*` slice as a parameter. Nav labels are `t.nav[link.id]` (`NavLink` has no `label`). Services items in json-server carry bilingual `LocalizedText` (`{ en, ar }`) fields (`title`, `description`, `image.alt`), picked with `useLocale()` — the API is expected to return both languages; the section heading/subtitle live in `t.services`. Other json-server content is not translated yet (English only). Styling uses logical properties (`inset-inline-*`, `padding-inline-*`, `text-align: start`); `[dir='rtl']` switches the font to Cairo and mirrors the project-card arrow and nav underline origin. New UI text must go in both `en.ts` and `ar.ts`.

**Toasts**: `react-toastify`, configured once in `components/common/Toast/Toast.tsx` (bottom-center, 3s auto-close, `limit={1}`) and rendered from the root layout. `showComingSoon({ title, message })` in `src/utils/toast.ts` keys the toast on its title so repeated clicks refresh rather than stack — it backs the header's Portfolio link and "View Case Study" (via `ComingSoonButton` inside `ProjectCard`); texts come from `t.comingSoon`. "Apply Now" no longer shows a toast; it links to a real destination (see Careers below).

**Careers apply flow**: `utils/careers.ts`'s `getApplyTarget(job)` decides where a job's "Apply" action goes: `Education` jobs with `job.application.method === 'external'` and a valid `https:` `externalUrl` get `{ kind: 'external' }` (opens the external form in a new tab); everything else gets `{ kind: 'internal', href: '/careers/${job.id}' }`; an `Education` job configured for an external form with an invalid/missing URL gets `{ kind: 'unavailable' }` (renders a disabled "Apply Unavailable" button). Both `JobCard` (careers list) and `CareerDetails` (detail page) call this same helper so the two surfaces never disagree. The internal path renders `ApplicationForm`, a client component with fields that vary by `job.type` (Education asks for a WhatsApp number via `utils/countryCodes.ts`'s country-code select, current level, and a short "about yourself"; Role/Internship ask for email and cover letter) and validates via `utils/validation.ts`'s `validateApplication`. Submission is intentionally disabled (`SUBMISSIONS_OPEN = false` in `ApplicationForm.tsx`) until a submission/file-upload destination is defined — flip that flag when wiring it up.

**Contact form**: `hooks/useContactForm.ts` owns typed form state (`handleChange` reads the input's `name` and ignores anything that is not a `ContactFormValues` key), client-side validation (required fields, email format, min message length), and accessible error messaging (`aria-invalid`/`aria-describedby`). Submission goes through `services/contactService.ts`, which always POSTs to the local `app/api/contact/route.ts` route handler (not through `apiClient`/json-server). That route validates the payload server-side, then sends the message via `resend` using `components/common/resend/email-template.tsx` as the React email body; it requires `RESEND_API_KEY`, `CONTACT_EMAIL` and `EMAIL_FROM` to be set (see Env vars above) and returns a 500 JSON error if email sending fails or the env vars are missing.

**Styling**: SCSS Modules per component (`*.module.scss`); shared design tokens in `src/styles/_variables.scss` (brand: Navy `#0B2A4A`, Mint `#2DD598`, White — surface shades for cards/panels/footer/badges are derived from navy). Responsive breakpoints are SCSS mixins (`up`/`down`) in `src/styles/_mixins.scss`, with four target ranges: desktop ≥1200px, laptop 992–1199px, tablet 768–991px, mobile <768px.

**Path alias**: `@/*` maps to `src/*` (see `tsconfig.json`).

**Lint note**: `@next/next/no-img-element` is intentionally disabled — plain `<img>` is used to preserve exact layout. `@typescript-eslint/no-explicit-any` is an error; unused vars are errors except when prefixed with `_`.
